# Targeted development interactions v3

Dataset-owner decision: the four exact v2 manifests in the separate baseline decision record are accepted as a versioned development baseline. This does not accept a team experiment or publish anything. The merged schema-1.1 CSP adapter remains the selected tool implementation. Shared wording and consistent message roles/tool exposure apply across compared models, preserving the no-tools versus model-translated-CSP arm difference.

The additive v3 bundle is a privileged evaluator review artifact, not an old-harness-compatible export. It contains 48 seeded candidates: four parameter bases for each of three constructions, with original, relaxA, relaxB and relaxBoth states. Duration is 2–4, release offset 0–2 and positive gap 1–2 minutes. All are one-day/two-job instances with at most three rooms and two surgeons. No new solver or proof vocabulary is introduced.

Eligibility × fragmented room: expand the first job's eligibility or merge the fragmented room windows. Eligibility × room gap: set the occupied room gap to zero or expand both jobs' eligibility to a full alternative room. Surgeon gap × fragmented surgeon: set surgeon gap to zero and/or merge surgeon windows. The first two have I/F/F/F labels; the last has I/I/I/F. Complete four-way contrasts demonstrate effects within these selected constructions only. They do not establish broad interaction difficulty. Seven other previously structural-only pair types remain unresolved, including optional-job effects, which cannot be inferred from optional presence under omission semantics.

All candidates are checked by complete bounded oracle enumeration, actual merged CSPAdapter invocation and intended-instance evidence validation. Twenty oracle-negative contrast states remain quarantined because the native tool returns UNKNOWN without the supported compact pair proof. Only 28 feasible controls are admitted; no negative proof is manufactured. All 48 are related development material, not a holdout. Numeric variants and ablation descendants share ancestry. Replay compares the full deterministic bundle, including source hashes; current evidence recomputation cannot authenticate a historical invocation.

The new trusted-local in-memory audit replays the complete bounded construction and validation. It requires explicit v3 identity and complete status. It is not an untrusted filesystem loader or a live-run registration. Old v2 exports/contracts remain unchanged and cannot silently accept v3. Input preparation projects only shared instruction, arm instruction and derived text; join IDs and all gold/receipts stay evaluator-side. The actual-ID text view is reused unchanged. A future general runner must explicitly register this new version before use.

## Non-secret settings and message assembly

`development_settings_v1.py` accepts only a strict JSON file/string, with duplicate keys/nonfinite values rejected. There are no environment overrides, so there is no file/environment precedence ambiguity. The example JSON deliberately leaves every experimental selection null. Provider/model revision, corpus version/hash, explicit unique case IDs, repetitions, spending ceiling, token/wall/tool limits, retry/order/seed must be supplied. Credentials and extra keys are rejected. Current conservative prototype limits include wall ≤60 seconds, CSP calls ≤4 and no retries. These are software validation bounds, not an approved research budget or selected protocol. Syntactic validation grants no execution approval; identity/membership still requires corpus preflight.

Provider-neutral assembly v1 uses a system message containing the exact shared instruction followed by the arm instruction, and a user message containing only validated instance text. The no-tools arm exposes none. Every compared model's CSP arm must receive the same pinned model-translated schema-1.1 tool. This module declares that policy but does not construct provider tool serialization or enforce a live provider. Unsupported provider role/tool adaptations must fail closed in any later adapter rather than silently alter the comparison. Only validated model text should be passed to assembly; it is not a gold-leakage sanitizer.

Remaining values for the team to fill: provider/model revision, selected corpus/case plan, repetitions, token/wall/tool/spending limits, order and seed. The retry setting is currently fixed at zero; broader retry policy needs explicit later implementation/review. No provider compatibility, model run, spending or experiment acceptance is implied.
