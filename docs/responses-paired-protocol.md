# Direct Responses paired protocol — local preparation

This revision implements the user-approved API format. It makes no live call, chooses no model or entitlement, stores no credential and authorizes no spending. It is separate from Allan's historical Claude Code experiments and the prior CLI adapter. Do not pool their results.

## Versioned boundary and ordering

`responses_runner.py` (`responses-paired-runner-v1`) and `responses_transport.py` (`openai-responses-text-json-v1`) use the fixed public endpoint `https://api.openai.com/v1/responses`. Python standard-library HTTPS is used directly: no SDK, automatic retry, redirect, proxy-environment lookup, alternate endpoint, model fallback or native API tool invocation. Non-200 responses and failures are retained, not retried. No provider-specific CLI or agent harness is involved.

Initial case text remains byte-identical across arms, from the same audited registered selection. Request `instructions` holds shared/arm instructions plus the common JSON-only rule; `input` holds case text, the existing final-output/text-CSP schema and explicit earlier submitted instances/results. The common application text protocol reuses source-pinned `study.prompts.user_message('v1',...)`; it does not reuse a Claude model identity or CLI transport. Responses serialization has its own version. `tools=[]`, `store=false` and `stream=false` are explicit. Only a text `csp` request can reach the local checked CSP; native API tool output is rejected. `store=false` is a request setting, not a promise about every provider retention policy.

`counterbalanced_pairs` uses an explicitly seeded initial offset, then alternates the first arm by case position. Each repetition reverses each case's starting arm. Even case counts balance exactly within each repetition; odd counts differ by one and balance across an even number of repetitions. Case shuffling is separately explicit/reproducible. The seed controls local ordering only, not model sampling. Every case/arm/repetition slot and attempt ID is frozen before provider construction. Failures, UNKNOWN and interrupted/missing slots remain in denominators; no overwrite, rerun or replacement occurs.

The old paired_runner.py, provider, shared receipt implementation and source-pin dependencies remain unchanged. This deliberately separate runner preserves old plan assessability while reusing frozen scoring, checked CSP, registrations and receipt retention. The small versioned engine duplication avoids silently changing archived CLI semantics. Old plans are not converted into API plans.

## Model, settings and estimate identity

Use `responses_transport.binding(model, expected_model, profile, effort, max_output_tokens, call_wall_seconds, call_budget_usd, rates)` after choices are approved. It reads source files only, not credentials/environment values. It pins Python runtime, adapter dependencies, receipt limits, rates/source and model identifiers. Returned model must match expected_model; mismatch retains tokens but makes cost estimation unknown and fails the attempt.

The implemented real profile is `gpt-6.1-sol-text-json-v1`, with explicit reasoning effort low/medium/high/xhigh/max and bounded max_output_tokens. GPT-6.1 Sol is a supported candidate, not a selected model. Other models/settings fail closed pending their own reviewed capability profile. Temperature, top-p and model sampling seed are not silently sent or dropped; no overrides are implemented. The mock-only profile cannot run live. The example leaves unresolved model, limits, selection and rates null. Valid syntax/fingerprints are not execution approval.

Token usage comes from reported input_tokens/output_tokens; reasoning tokens are already part of output_tokens and are not added again. Cached-input counts are separately retained. Missing/inconsistent required usage stays unknown. Dollar fields are named cost_estimate_usd, derived from pinned input/cached-input/output rates; billed_cost_usd is always null because the response does not establish an invoice. Estimates prove neither charges nor credit eligibility. Unknown estimated cost stops new slots. Estimated overruns remain failures, not erased or retried. Output caps/socket timeouts do not provide a hard total-input-token, whole-attempt, memory, billing or remote-cancellation guarantee. Socket timeout is not a total end-to-end deadline; post-return attempt checks still apply.

## Credential boundary and template

`.env.example` is key-free. `.env`, `.env.*` and nested local variants are ignored; the example is explicitly allowed. There are no environment overrides or environment-value inspections. `responses_credentials.load_key_file(path)` is an explicit future loader: one unquoted OPENAI_API_KEY assignment, no interpolation/evaluation/additional keys, owner-only regular file, no symlink, at most 8 KiB. It never writes/copies a credential. Actual creation, entry, access, storage and live use need separate action-time authority; none happened here. A real .env would contain plaintext key material, which must be disclosed and approved before setup.

Preflight/mocks never load a real key. Live execution requires a fully bound live configuration, explicit allow_live and supplied key loader. The CLI also requires --allow-live and --allow-key-file. Authorization headers/loader output stay inside the HTTP call, never plans, receipts or exceptions. Errors record fixed class/status, not raw exception text. Only allowlisted response headers are retained. Full-key echoes in HTTP bodies/headers are defensively redacted before retention. This is not a general secret detector for arbitrary user text/configuration; never put credentials in settings, rates.source, dataset text or arguments.

The implemented authentication route is API-key-file access only. Eligible ChatGPT-plan Responses routes for authorized local/open-source apps and possible API credits exist, but this account's eligibility, activation and balance are unverified. OAuth/token sharing is not implemented. Other apps' tokens must not be extracted/reused. API use is neither assumed always separately paid nor assumed included.

## Interface and limits

`python3 tools/run_responses_paired.py --datasets DATASETS.json --config CONFIG.json --out NEW_DIRECTORY --allow-live --allow-key-file --key-file .env` is a future command, not run here. Without both opt-ins it refuses before key access. Config/source/data validation precedes the loader. Offline tests inject fake HTTP into ResponsesAdapter; mock/live mismatch fails closed. The prepared four-case trial and previous evidence remain untouched.

Receipts retain HTTP bodies/model text, response IDs, returned model, usage, client wall time, incomplete details and fixed error classes. Oversized HTTP bodies retain the received bounded prefix with response_complete=false/resource_bound; it cannot become complete output. Unchanged shared receipt/archive limits apply. Active-call interruption may leave its slot missing; previous flushed receipts remain assessable. No hard memory/disk quota is enforced; these are software limits, not team research quantities.

Before real execution: select the model/snapshot and supported settings; approve authentication/entitlement and any plaintext credential setup; pin current rate estimates and a bounded budget; then generate a fresh plan. No paid trial, sign-in, installation, credential setup, commit or publication occurs in this revision.

Official documentation checked from xlogin: https://developers.openai.com/api/docs/quickstart ; https://developers.openai.com/api/reference/resources/responses/methods/create ; https://developers.openai.com/api/docs/models/gpt-6.1-sol . Verified source context also supplied https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference and https://developers.openai.com/api/docs/guides/chatgpt-api-credits ; neither route was checked against this account.

Assessment recomputes parsed usage/rate estimates and model text from the retained HTTP body, then joins the exact final-output span to the independently scored receipt. This detects internal disagreement; hashes/request IDs do not authenticate historical invocation against a malicious receipt author. Client retries are disabled, while provider-internal scheduling/retries are unobserved. A returned model identifier is checked, not a cryptographic proof of immutable weights. Visible shared system instructions are preserved byte-for-byte from the existing JSON text protocol.
