## What is reusable

`benchmark_datasets.load(specs)` explicitly preflights selected Tier A, seeded-v2, interactions-v3 or Allan hard packages. Each spec has exactly kind, directory, plan; its version-specific existing plan and package identities are required. Unsupported/mixed/tampered packages and duplicate/unknown/excluded IDs fail closed. Multiple packages may be explicitly selected, never implicitly pooled.

Tier A retains 15 source cases, 9 evidence-eligible and 6 oracle-only validation cases; the six do not enter model denominators. The accepted v2 baseline retains 240 candidates/200 admissions(105 feasible, 95 negative) and 40 quarantines across four profiles. V3 retains 48 candidates/28 normalized structures and 28 feasible admissions/17 structures;20 controls remain quarantined. QA fixture copies are byte-identical snapshots, not extra cases.

Allan's hard source remains100 cases/50 related pairs with50 checked witnesses and 50 checked compact certificates. Its separate bounded-tool lane has 51 supported(6 feasible/45 negative) and 49 UNKNOWN(44 feasible/5 negative). Catalog identities expose full source membership, checked-gold count, tool-support diagnostics, selection-policy version and selected IDs separately. UNKNOWN tool support never changes the checked gold label. A51-case plan is a disclosed selected lane, not the full harder comparison or a representative sample. No full100-case alternative policy is silently enabled.

`paired_runner.make_plan(specs,settings)` binds catalog/source/instruction identities, explicit case/arm/repetition slots, local order seed, run identity and per-slot attempt identities. Settings must match the registration repetitions. `run(...,provider_factory,solver_factory)` creates a new private directory; it refuses any existing destination, writes plan.json before provider construction, appends attempts.jsonl with flushing and writes a separate summary. No retry or replacement is supported. `assess_saved(specs,directory)` recomputes evidence/summaries from the original plan and available receipts after an interruption; source/data drift, duplicate/unplanned attempts and raw/normalized disagreement fail closed. It does not execute missing slots.

Every planned slot stays in denominators. Raw supported finals are retained and strictly JSON-parsed, never repaired or stripped from prose. Frozen `tier_a_contract.output_verdict` checks intended-instance evidence; `tier_a_completion.well_formed` supplies the merged completion proposal's shape boundary. Wrong well-formed answers are answer-complete but not successful; malformed finals, timeouts without a well-formed final, and missing receipts produce incomplete pairs. `evidence_success` is unadjusted checker success; `success` also excludes recorded operational failures and explicit measured budget violations. These new summaries do not alter legacy receipts/results.

Token/cost gaps stay null with coverage/reasons; known subtotals are separate. Unknown cost or an exhausted spending ceiling stops NEW slots without dropping the plan. Actual overruns remain recorded failures, no automatic rerun. Timing and provider/solver limits are cooperative and checked after callbacks return; this in-process software cannot preempt an arbitrary blocking plug-in. It is not a hard wall-clock/spend enforcement system. No provider charging, pricing or billing inference is implemented. Seed controls local case ordering only, not a model's generation seed.

## Provider-neutral fixture API

A factory receives no case, gold or evaluator metadata and returns an object with `offline=True`, explicit `revision`, and `respond(messages,tools,limits)`. Fixture mode rejects live-provider objects. The separately opted-in pinned Claude route is documented in the v2 provider guide. Initial roles are system(shared instruction plus the explicit arm instruction), user(identical derived case text). Follow-up assistant/tool messages contain only model-translated arguments and solver results. `tools=[]` for no_tools; csp receives the same pinned schema 1.1 tool definition. Model/provider-specific serialization is not silently assumed.

Return exactly either `{type:'final',raw:JSON_text,usage:...}` or `{type:'tool_call',name:'csp',arguments:{instance:translated_schema_1_1},usage:...}`. Usage is null or reported input_tokens, output_tokens, cost_usd; missing/invalid fields remain unknown. Limits passed to respond contain remaining token_limit, wall_seconds and spending_remaining_usd. These limits are operational metadata, not model-facing prompt fields. No case/family IDs, labels, eligibility, lineage, witnesses, certificates, run IDs or gold structures enter this API. Actual patient/resource IDs in controlled text/evidence are necessary task content. API separation is not a sandbox against malicious same-process plug-ins or a claim of provider adherence.

`offline_provider_example.OfflineTranslator` parses the supplied controlled text as a fixture, returns UNKNOWN without tools, and otherwise translates text then returns the checked tool result. Its zero token/cost usage means literally no model call. Its outputs are plumbing QA, never LLM performance or a no-tools algorithm benchmark. Ordinary derived inputs contain no absent-ID example; originals are preserved. The internal fixture parser's inverse transformation is not sent as a prompt.

## Allan solver integration: three steps

1. Wrap the existing solver in a small object exposing `revision`(exact version string),`schema_version='1.1'`,`supported_limits={'max_nodes':100000,'seconds':2}`, and `invoke(arguments)`. Arguments contain exactly one `instance`: the model translation. No intended instance or repair/scoring handle is supplied. The example `solver_interface.MergedSolver` delegates directly to existing `CSPAdapter.invoke`; it does not implement DFS again.
2. Return the existing FEASIBLE/schedule, INFEASIBLE/pair_order_impossible certificate, or UNKNOWN/reason shape. Optional nodes/search_exhausted metadata is checked. The wrapper checks evidence on the translated instance, records the original bounded JSON result and timing, and maps malformed/unsupported/timeout outcomes to UNKNOWN plus diagnostics. Exhausted search/native INFEASIBLE without a supported checked compact proof cannot become certified success. External final scoring always checks the intended instance independently. A custom plug-in must enforce its declared limits itself; the wrapper also detects elapsed overruns after return.
3. Run `timeout 60s env PYTHONDONTWRITEBYTECODE=1 python3 tools/run_offline_tests.py test_solver_interface.py` and `test_paired_runner.py`, then the full suite normally and under -O. Inject the reviewed factory via `run(...,solver_factory=YourSolver)` with an explicitly matching revision/limits setting. No new solver source or OR-Tools dependency is assumed. Unsupported versions/limits fail closed; different proof vocabularies need explicit contract review.
